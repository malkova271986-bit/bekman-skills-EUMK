# ЭУМК в виде офлайн HTML-комплекса

Результат — папка, которая открывается без интернета и установки: двойной щелчок по `index.html`, слева меню по разделам, справа материал; все материалы связаны гиперссылками. Плюс отчёт о сверке материалов.

Образец, собранный для курса «Проектирование учебных занятий в информационно-образовательной среде» (ГрГУ, 08.10.2026; обложка и состав разделов — 26.10.2026): скрипты в `/mnt/project-files/ЭУМК_HTML/_сборка/` (`build.py`, `check.py`, `dec.py`, `renum.py`, `shot.js`, `map.json`). Если папка доступна, копировать скрипты оттуда и менять только описание курса; если нет — писать по спецификации ниже.

## Правила, которые не нарушаются

- Исходные файлы на Диске не изменять (исключение — переименование файлов по прямой просьбе автора, см. раздел 4). Всё собирать в отдельной папке.
- Авторский текст не переписывать: допустимы только разметка и оформление. Содержательные правки — только по прямому поручению автора, только в копиях внутри комплекса, и каждая правка перечисляется в отчёте. Оригиналы на Диске правятся, только если автор отдельно об этом попросил.
- Никаких внешних CDN, веб-шрифтов, iframe с внешними сайтами. Всё внутри папки.
- Общение с автором — по-русски, научным стилем, пошагово и без технического жаргона.

## 1. Опись материалов

1. Получить ссылку на папку Диска, название дисциплины, специальность, автора, семестры.
2. Обойти дерево папки (`search_files` с `parentId = '<id>'`, рекурсивно). Обычные разделы ЭУМК: 1 Пояснительная записка; 2 Теоретический раздел (лекции); 3 Практический раздел; 4 Раздел контроля знаний; 5 Вспомогательный раздел (учебная программа, содержание учебного материала, учебно-методическая карта, литература); Документы ЭУМК (титул, заявка, рецензии). Документы ЭУМК в комплекс отдельными страницами не включаются: рецензии и заявка не учебный материал, а сведения титульного листа идут на обложку главной страницы (см. раздел 4).
3. Записать опись: название, id, тип, дата изменения. Дата изменения пригодится при повторной сверке: перекачивать только изменённое.

## 2. Выгрузка

- Google Slides → `download_file_content` с `exportMimeType: application/pdf`.
- Крупные Google Docs (таблицы, карта, тесты, вопросы) → `text/html`.
- Небольшие Docs (титул, рецензии, записка) → `read_file_content` (markdown), сохранить в `md/*.md`. Их HTML-экспорт приходит плохо.
- Ответ больше лимита сохраняется в `tool-results/*.txt` как JSON `{content(base64), title, mimeType}`; декодировать `dec.py <json> <выход>` (запускать `python3 -I`).
- Выгруженное класть в `src/`, свои скрипты — в отдельную папку `tools/`.

## 3. Сверка (до сборки)

Проверить и записать в `Замечания по сверке.md` (разделы «Исправлено» / «Осталось» / «Технические особенности»):

- **Карта ↔ занятия.** Каждой теме учебно-методической карты должна соответствовать лекция или практическое занятие с тем же названием (название занятия брать с титульного слайда: `pdftotext -f 1 -l 1`). Выписать темы без занятия и занятия без темы. При расхождениях подготовить файл вариантов переименования: для каждой пары вариант А (название занятия без изменений) и вариант Б (сводная формулировка: рамка темы карты + конкретный сервис из занятия).
- **Семестры и нумерация.** Занятие должно стоять в нумерации того семестра, к которому относится его тема. Отдельно — порядок строк карты против нумерации занятий.
- **Язык.** Английские тексты и дубликаты (например, перевод вопросов после русского текста), английские подписи.
- **Чужие фрагменты.** Следы другого ЭУМК: иная дисциплина или специальность («менеджмент», «магистранты» вместо «студенты»), старые даты и номера протоколов.
- **Согласованность документов.** Зачёт или экзамен; часы в записке против программы и плана; устаревшее ПО (Flash Player); незаконченные строки; кавычки и пунктуация на титуле.
- **Целевая аудитория заданий.** Например, задания про дошкольников в курсе для начальной школы.
- **Тесты.** Число заданий, разделов, вариантов ответа; длина ключа равна числу заданий.
- **Технические моменты.** Внешние картинки и рисунки Google (без интернета не видны), слайды без текстового слоя (не ищутся).

Отчёт отдаётся автору до или вместе с первой сборкой. После правок автора — повторная сверка по датам изменения.

## 4. Сборка (`build.py`)

Устройство результата:

```
<ASCII_ИМЯ_ПАПКИ>/
  index.html                 главная: обложка-титул, путеводитель, быстрые ссылки по разделам
  KAK_OTKRYT_prochitayte.txt инструкция (UTF-8 с BOM)
  materials/
    *.html                   каждая страница со своим боковым меню (без iframe)
    assets/style.css, app.js
    slides/<id>/001.jpg …    слайды, pdftoppm JPEG шириной 1280
    pages/<id>/…             постраничные PDF шириной 1100
    files/*.pdf              PDF для печати и скачивания
    search-index.js          window.SEARCH_INDEX — поиск работает на file://
```

Что менять в `build.py` под новый курс: `COURSE`, специальность; `SECTIONS`; реестр страниц `add(pid, group, title, short, kind=...)`, где kind — `deck` (слайды), `pages` (PDF постранично), `bigpdf` (PDF во встроенном просмотрщике), `md`, `gdoc` (HTML-экспорт Docs); `MAP_LINKS` (номер темы карты → id страницы); `SECTION_OF` (страница → раздел программы по теме карты); источники `html_src`; данные обложки в `home_page()`.

Обязательные функции:

- **обложка на главной** (`<section class="cover">` в начале `index.html`, вместо отдельной страницы «Титульный лист»): оформлена как титульный слайд. Сверху — учреждение образования, факультет и кафедра мелкими прописными буквами. Затем надпись «Электронный учебно-методический комплекс» акцентным цветом и название курса крупным шрифтом с засечками (Georgia / Times New Roman, системные). Под ним короткая цветная черта и строка «Специальность · форма получения образования · курс · семестры». Внизу, под тонкой линией, две колонки: «Автор» и «Рецензенты» (кафедра с учреждением; ФИО индивидуального рецензента с должностью, степенью и званием мелким шрифтом). Фон — диагональный градиент основного цвета комплекса (образец: #163f5f → #1f5f8b → #2b7a8c) с 2–3 полупрозрачными декоративными кругами через `radial-gradient` (не заходить ими под текст), акцент — тёплый (#e8a458 / #f3c58f), скругление 14px, тень. Без картинок и веб-шрифтов. На ширине ≤ 900px колонки встают в одну, кегль заголовка уменьшается; в печати `print-color-adjust:exact`. Все сведения брать дословно с титульного листа на Диске; подписи, «УТВЕРЖДЕНО/СОГЛАСОВАНО» и пустые строки протоколов на обложку не выносить. Текст обложки добавить в поисковый индекс главной страницы;
- заголовок занятия — с титульного слайда; восстанавливать дефисы, которые теряет pdftotext (ИИ-, ИКТ-);
- в учебно-методической карте у строк якоря `t<номер>`, названия тем — ссылки на материал;
- на каждой странице блок «Связанные материалы»: лекции и занятия того же раздела и ссылка на строку карты;
- очистка HTML Google Docs: убрать `@import` и внешние картинки, развернуть ссылки `google.com/url?q=`, внешним ссылкам `target=_blank`;
- просмотр слайдов во весь экран со стрелками, «Назад/Вперёд», печатная CSS, мобильное меню;
- предупреждение «Комплекс открыт прямо из архива…» с шагами распаковки: блок с inline-стилем в начале `<body>`, а в `style.css` правило `.unzip-warn{display:none!important}`. Если CSS не загрузился (страница вынута из архива), блок виден.

Содержательные правки, разрешённые автором, вносятся в `md/*.md` или в обработку конкретной страницы, с комментарием в коде. Порядок номеров лекций и занятий лучше привести к порядку тем карты на самом Диске: Claude переименовывает файлы (`update_file`, только название; при обмене номерами — через временные имена), автор меняет номер на титульном слайде (текст слайдов через API не редактируется), затем Claude перекачивает файлы и проверяет, что номер на слайде совпадает с именем файла. Если автор просит не трогать Диск, перенумеровать только в комплексе через словарь в `build.py` и `renum.py`: он рисует новый номер поверх старого на титульном слайде PDF, а цвет и кегль берёт со слайда.

## 5. Проверка (до отправки автору)

1. `python3 check.py <папка>/` — все внутренние ссылки и якоря; битых должно быть 0. Внешние ссылки перечислить.
2. Playwright (`shot.js`; node `require('/opt/node22/lib/node_modules/playwright')`): скриншоты изменённых страниц и обложки (ширина 1400 и 390); поиск находит результаты; просмотр слайдов открывается; на мобильной ширине 390 нет горизонтальной прокрутки; ошибок JS нет. Скриншоты просмотреть глазами.
3. Сверить комплекс с текущими версиями документов на Диске: названия, число слайдов, отсутствие удалённых материалов.

## 6. Упаковка для Windows

- **Все пути внутри архива — только латиница:** папка комплекса, txt-инструкция, PDF с кириллическими именами (сохранять как `<pid>.pdf`). Встроенный архиватор Windows искажает кириллические имена, и ссылки перестают работать.
- Архивировать через Python `zipfile`, затем `unzip -t`, распаковать в пустую папку и открыть `index.html` в Playwright.
- Сам `.zip` может называться по-русски.
- В сообщении автору всегда давать инструкцию: скачать архив → правой кнопкой «Извлечь все…» → «Извлечь» → в распакованной папке дважды щёлкнуть `index.html`. Не открывать `index.html` из окна архива: Windows достаёт одну страницу во временную папку (в адресе видно `Temp` и `.zip`), и остальные материалы дают «Файл не найден».

## 7. Передача и повторные сборки

- Архив, `Замечания по сверке.md` и скрипты сборки положить в общую папку проекта (`/mnt/project-files/ЭУМК_<курс>/`, скрипты в `_сборка/`), приложить к ответу. Скриншот обложки приложить при первой сборке и при изменении обложки.
- В ответе автору: что исправлено, что осталось за автором (по одному пункту), что изменено только в комплексе, а не на Диске.
- После каждой правки автора: перекачать изменённые файлы, повторить сверку, пересобрать полностью (со слайдами, если менялись презентации), `check.py`, скриншоты, переупаковать, обновить отчёт.
- Решения автора (перенумерация, разрешённые правки текста) записывать в память проекта, чтобы они сохранялись при следующих сборках.
